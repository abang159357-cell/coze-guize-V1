# 接入 coze-guize-V1 通用研发协议（可复制模板）

> 用途：把 `coze-guize-V1` 仓库的通用研发协议接入任何新项目，让 AGENT 自动遵守。**本文件可整体复制到目标项目，或按下方「一句话接入」直接触发接入。**
>
> 协议版本基线：**`coze-guize-V1 V13`**（对应仓库 `core/通用研发协议.md` 登记版本；对应 commit 见 `VERSION.md`）。

---

## 一、一句话接入（最快，给其他项目窗口或 AGENT 用）

> 目标项目窗口直接粘贴下面这句即可触发完整接入，无需再解释规则：

```
按 coze-guize-V1 仓库 https://github.com/abang159357-cell/coze-guize-V1 的通用研发协议 V13 接入本项目：
1. 读取该仓库的 `core/通用研发协议.md`（权威源）与 `checklists/` 两份清单，按其内容初始化本项目 `AGENTS.md`（并入协议固定章节 + 填写本项目专属上下文）；
2. 在本项目 `AGENTS.md` 登记规则基线 = 来源仓库 `coze-guize-V1` + 协议版本 `V13` + 登记时 commit（见仓库 `VERSION.md`）；
3. 之后每轮改动按 `checklists/交付前检查.md` 自检，上线按 `checklists/上线前后检查.md` 验收；
4. 涉及 GitHub/CI 的项目按 `workflows/Git与CI.md` 执行。协议后续变更须经项目所有者确认后才生效。
```

---

## 二、完整落地步骤（负责人逐步执行）

### 第 1 步：新建目标项目根 `AGENTS.md`
用仓库 `templates/AGENTS.md.template` 作为骨架，包含**两大部分**：
- **一、通用研发协议**：把 `core/通用研发协议.md` 在**登记基线（见第 2 步）**版本的内容并入此固定章节。
- **二、项目专属上下文**：填目标项目的概述 / 技术栈 / 目录结构 / 关键入口 / 运行预览 / 坑点。

### 第 2 步：登记规则基线
在本项目 `AGENTS.md` 顶部（模板第 5 行处）登记：

```
规则基线：来源仓库 `coze-guize-V1`；协议版本 `V13`（登记时仓库 commit = <git rev-parse HEAD>，见仓库 `VERSION.md`）。
协议后续变更须经项目所有者确认后升版本号才生效，不自动覆盖本基线。
```

### 第 3 步：配齐项目级配套（AGENTS.md 只是四件套之一）
| 配套 | 动作 |
|---|---|
| `.coze` | 为目标项目写合法 `.coze`（`project_type` / `sub_id` / `preview_enable` 等）|
| 类型 skill | web→`web-dev`、小程序→`miniprogram-dev`、App→`app-dev` |
| 部署判定 | 加载 `general-deploy` 确认 `[deploy]` |

### 第 4 步：无人值守前落地执行计划
复制 `templates/执行计划.md.template` 到 `docs/执行计划.md` 并填实（目标/范围/授权边界/里程碑/停止条件）。**未落盘 `docs/执行计划.md` 不得进入无人值守开发。**

### 第 5 步：按强制清单走流程
- 每轮改动 → `checklists/交付前检查.md`
- 上线定版 → `checklists/上线前后检查.md`（上线前 + 对抗测试 + 上线后）
- 涉 GitHub/CI → `workflows/Git与CI.md`

---

## 三、规则基线登记格式（可复制）

```markdown
## 变更记录
- 登记日期：<YYYY-MM-DD>
- 规则基线：来源仓库 `coze-guize-V1`，协议版本 `V13`，登记时 commit `=<git rev-parse HEAD>`（见仓库 `VERSION.md`）
- 后续协议变更须经项目所有者确认后升版本号，登记处同步更新，不自动覆盖既有基线
```

---

## 四、接入自检清单（接入是否成功）

- [ ] 目标项目根 `AGENTS.md` 已含"通用研发协议"固定章节 + 本项目专属上下文
- [ ] 已在 `AGENTS.md` 登记规则基线（`coze-guize-V1 V13` + commit）
- [ ] 目标项目 `.coze` 已合法、类型 skill 已加载、部署配置已由 `general-deploy` 判定
- [ ] （如需无人值守）`docs/执行计划.md` 已落盘并填实
- [ ] 交付前检查 + 上线前后检查可作为目标项目强制验收依据
