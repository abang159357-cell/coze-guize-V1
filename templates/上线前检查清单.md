# 上线前检查清单（执行模板）

> 本文件是 `checklists/上线前后检查.md` 的**操作化执行模板**，其判定标准与结论权威以该文件为准；**本模板不改写权威源，也不得脱离权威源自行扩增条款**。
>
> **适用原则**：
> - **通用项不可豁免**：基础质量 / 功能可用 / 安全边界 / 关键数据完整性等必须满足；
> - **业务触发项按有无该业务决定**：有用户内容、有写接口、有个人数据、有部署/回滚条件时按相应条款执行；
> - **形态项按项目类型裁剪**：纯脚本、纯文档、无用户内容等项目按真实形态声明“本形态不适用 + 原因 + 降级”；
> - **跳过项必须写明“未测 + 原因 + 降级”**，不得默认为通过；
> - **任何缺证项都不能用“看起来没问题”掩盖**，必须如实记录风险。

## §〇 适用面（先核形态，再决定必做/裁剪）

在开始逐项执行前，先明确：

- [ ] 本项目是否有真实运行服务 / 部署产物？
- [ ] 是否存在用户内容、写接口、个人数据、权限边界？
- [ ] 是否存在高并发 / 重量级查询 / 外部依赖断连风险？
- [ ] 是否已做生产配置与回滚准备？
- [ ] 是否存在可见 UI / 表单 / 页面跳转？

### 适用裁剪模板

- 若“无服务 / 无用户内容 / 无写接口 / 无个人数据 / 无线上部署”：
  - 仅保留：基础质量、构建正确性、最小真实探活、风险说明；
  - 其余需按“不适用 + 原因 + 降级”写明。
- 若“有服务、有用户内容、有写接口、有个人数据”：
  - 必须按本模板逐项执行，尤其是权限安全、数据一致性、审计日志、回滚与合规。
- 若“有高并发 / 高风险依赖 / 线上部署”：
  - 必须补充性能、断连降级、回滚与线上探活。

### 证据命令（适用面）

- `git status -sb`
- `git diff --stat`
- `git log --oneline -n 10`

---

## §一、Git 基础与交付基础（上线前必须核）

### 1. 交付范围与脏工作区

- [ ] 本次变更是否只包含目标范围，无夹带无关文件？
- [ ] 是否清理了临时文件、日志、截图、密钥、缓存、临时 env、历史附件？
- [ ] 是否留有未说明的副作用、顺手重构或“看起来方便”的无关修正？
- [ ] 是否已确认本地分支与远端同步，无未推送未审查提交？

### 2. Git 与推送门禁

- [ ] `git status -sb` 无未跟踪脏文件或未审查内容；
- [ ] `git diff --stat` 仅包含本次目标范围；
- [ ] 若临时目录/缓存/大文件已进入仓库，已进行清理并说明；
- [ ] 若本次修改涉及目录或路径变更，已同步更新 `INDEX.md` / `README.md` / `AGENTS.md` 及必要文档引用。

### 证据命令

- `git status -sb`
- `git diff --stat`
- `git log --oneline --decorate -n 10`

---

## §二、CI 门禁与静态质量（必须通过）

### 3. CI / 打包质量门禁

- [ ] 项目已绑定 GitHub Actions 或等效 CI；
- [ ] `pnpm install --frozen-lockfile` 成功；
- [ ] `typecheck` / `lint` / `build` / 单测已在 CI 中执行；
- [ ] 若使用 pnpm，`package.json` 的 `packageManager` 与 workflow 的 `pnpm/action-setup` 版本一致；
- [ ] workflow 权限最小化，第三方 action pin SHA，不使用漂移版 tag；
- [ ] CI 失败时是否能在日志中直接定位到失败步骤 / 文件 / 代码位置。

### 4. 静态质量结论

- [ ] 构建正常，且本次改动没有产出“可编译但运行时错误”的假绿；
- [ ] 若未做 build / typecheck / lint / test，则必须在本节写明“不测 + 原因 + 风险 + 降级方案”。

### 证据命令

- `pnpm install --frozen-lockfile`
- `pnpm lint`
- `pnpm typecheck`（若项目支持）
- `pnpm test`
- `pnpm build`

> 注：CI 绿只证明“构建正确 + 静态质量”，不能证明页面或业务链路实际可用；它是第二道防线，不能替代真实功能验证。

---

## §三、功能可用性与交互完整性（通用项，必须验证）

### 5. 页面 / 入口 / 交互网络闭环

- [ ] 每个可点击入口、按钮、导航、搜索框、链接、表单与提交操作，都已真实点击或真实请求验证；
- [ ] 路由/URL/跳转地址真实存在，不存在死链；
- [ ] 关键页面能正常渲染，且显示内容不丢失；
- [ ] 提交表单能真实生效，且有返回结果或落库/触达预期行为；
- [ ] 关键链路（浏览 → 搜索 → 详情 → 提交 → 审核/展示）真实走通；
- [ ] 页面/接口返回空数据、超长文本、重复提交、弱网/断网情况下不崩、不误判。

### 6. 核心功能是否真实走通

- [ ] 真实用户路径（不是 mock）已走一遍；
- [ ] 真实请求/真实页面打开均已验证；
- [ ] 如果未能真实走通，必须写明：缺口、风险、降级、是否可上线。

### 证据命令 / 方法

- 浏览器或官方验收工具打开页面；
- `curl` / `fetch` / 接口实际请求；
- 关键日志与返回结果；
- 页面截图、用户旅程记录或真实数据变更记录。

---

## §四、权限与安全（业务触发项：有用户内容/写接口/个人数据时必须做）

### 7. 权限边界

- [ ] 匿名用户不能直接写入 / 发布 / 修改 / 删除；
- [ ] 未授权用户不能访问他人数据；
- [ ] 越权访问他人字段/记录已实测并被阻止；
- [ ] 敏感配置（密钥、Service Role、安全令牌）未出现在前端或仓库；
- [ ] 管理权限只在服务端/环境变量判定，前端参数不能绕过。

### 8. 注入与安全探针

- [ ] XSS 注入载荷已验证为不执行；
- [ ] SQL / 命令 / 模板注入在关键输入点已验证为被拒绝或转义；
- [ ] 关键 API 的输入输出都经过必要校验和限制；
- [ ] 关键权限/数据过滤点真实生效。

### 证据命令 / 方法

- 真实请求构造：匿名请求、越权请求、伪造参数请求；
- 401 / 403 / 400 响应记录；
- 注入载荷验证记录；
- 安全扫描工具（如 SAST / Semgrep / CodeQL 等，若启用）记录。

> 若本项目无用户内容/无写接口/无权限边界，则在本节写明“本形态不适用 + 原因 + 维持基础安全检查”。

---

## §五、数据一致性与核心业务规则（业务触发项：有核心规则/权限过滤/排序/状态流转时必须做）

### 9. 关键规则真实验证

- [ ] 核心业务规则是否真实执行（排序、权限过滤、状态流转、自动降权、时间窗口等）；
- [ ] 关键数据更新后，读取端状态是否一致；
- [ ] 空数据、重复数据、冲突状态是否被正确处理；
- [ ] 若本项目无核心业务规则，则写明“不适用 + 原因”。

### 证据方法

- 单元测试 / 集成测试 / 真实数据流验证；
- 数据库查询结果；
- 用户真实操作后的状态检查。

---

## §六、性能与稳定性（形态触发项：有服务/高并发/高数据量时必须做）

### 10. 稳定性与压力基线

- [ ] 关键查询在数据量增加时仍能接受；
- [ ] 依赖(数据库/第三方)断连时系统能优雅降级；
- [ ] 高并发场景不崩；
- [ ] 若未做压测，需写明“未测 + 原因 + 风险 + 降级方案”。

### 证据方法

- 简单压测脚本；
- 响应时间记录；
- 依赖断连/重试测试；
- 关键功能对大数据量的探活记录。

---

## §七、依赖治理与 CI 安全基线（必须检查）

### 11. 依赖安全与来源

- [ ] 关键依赖已确认是 runtime 依赖还是 dev-only；
- [ ] 依赖扫描结果已核实真实风险，不仅看告警总数；
- [ ] 若存在升级，已确认升级版本与 lockfile 一致；
- [ ] 若存在“不适用/暂缓”的依赖，已给出证据与原因；
- [ ] workflow / CI 配置已满足最小权限、固定版本和安全门禁要求。

### 证据命令

- `pnpm audit --prod`
- `pnpm why <pkg>`
- `grep '^  <pkg>@' pnpm-lock.yaml`

> 注意：构建绿不能代替依赖升级后的真实运行时验证；真实链路冒烟仍必须做。

---

## §八、运营与合规（业务触发项：有用户内容 / 个人数据 / 写操作时必须做）

### 12. 线上运营与追溯

- [ ] 备份与恢复已确认；
- [ ] 写操作留日志、时间戳、审计链路齐全；
- [ ] 审核、下架或举报闭环存在；
- [ ] 关键外部依赖（DB / 登录 / 存储 / 域名 / SSL）已准备好；
- [ ] 隐私合规与风险边界已核对；
- [ ] 回滚路径已明确，并可执行。

### 证据方法

- 备份恢复演练；
- 审计日志记录；
- 线上/真实环境访问验证；
- 回滚脚本或流程说明。

---

## §九、部署与环境变量（部署项目必须核）

### 13. 部署就绪

- [ ] `Dockerfile` / `build` / `start` 等入口真实存在且一致；
- [ ] 容器能构建成功；
- [ ] 应用能启动，并具备健康探活（如 `/health`）；
- [ ] 生产/部署变量已确认并真实读取，不依赖隐式默认值；
- [ ] 若有域名、HTTPS、环境变量、静态资源地址，均已校准正式配置；
- [ ] 若上线前未验证部署，必须写明“不测 + 原因 + 风险 + 降级”。

### 证据命令 / 方法

- `docker build -t <image> .`
- `docker run ...` + 健康探测
- `curl -f http://127.0.0.1:<port>/health`（如平台支持）
- 生产 env / 代码读取点核对（`grep` / 搜索）

---

## §十、总体结论（上线前必须逐项给出，不得留白）

请在最终写出以下结论：

### 10.1 必做项

- 已完成项：
  - 例：CI 通过；构建成功；关键链路已走通；权限边界已验证；回滚路径已确认。
- 未完成项：
  - 例：未测性能大并发；未验证某个审核流；某个配套脚本未执行。

### 10.2 业务触发项

- [ ] 权限安全：是 / 否 / 本形态不适用（原因：...）
- [ ] 数据一致性：是 / 否 / 本形态不适用（原因：...）
- [ ] 运营合规：是 / 否 / 本形态不适用（原因：...）
- [ ] 备份/审计/回滚：是 / 否 / 本形态不适用（原因：...）

### 10.3 形态裁剪项

- [ ] 本形态是否为静态站 / 文档 / 脚本 / 内部工具 / 高并发服务 / 多用户服务？
- [ ] 对应未适用条目已写明：`未测 + 原因 + 降级`。

### 10.4 最终判定

- [ ] 可上线
- [ ] 有条件可上线
- [ ] 不可上线
- [ ] 需延期

### 10.5 结论模板

> 已测项：...  
> 未测/受限项：...  
> 风险与待决项：...  
> 最终判定：...  
> 原因/依据：...  

> **最终判定必须由人类/项目所有者确认；AI 只能提供证据与结论，但不能绕过最终审批。**

## 结论说明（权威源指引）

- 本模板的判断标准以 `checklists/上线前后检查.md` 为准；
- 本模板只作为“执行入口”和“操作化清单”，用于帮助项目逐条落地；
- 若权威源与本模板条文冲突，以权威源为准；
- 本模板禁止自行扩增“无依据”的强制条款或把“未适用”默认为“已通过”。

---

## 一次性执行顺序建议

1. 先核适用面（是否有用户内容 / 写接口 / 个人数据 / 部署 / 高并发）；
2. 再做 Git 基础与 CI 门禁；
3. 再做真实功能 / 权限安全 / 数据一致性；
4. 再做性能、依赖、部署和回滚；
5. 最后给出总体结论。

> 不要求一口气“无条件全打满”，但必须在每一项前确认“适用/不适用”，并留下明确证据；缺证即不得声称已验收。
