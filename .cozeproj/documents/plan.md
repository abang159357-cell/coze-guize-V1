# 计划：coze-guize-V1 仓库结构重设计

## 概述
把现有 `coze-guide` 仓库的通用研发规范内容（协议 V13、checklists、templates、依据、推送CI交接等）重组为新的 `coze-guize-V1` 仓库结构，目标有三：**①让内容更执行落地（分层：强制规则 / 流程框架 / 检查闸门 / 可直接套用模板 / 参考依据）；②让 AI 能清晰读取内容索引（INDEX 强映射 + 每次必读 AGENTS.md）；③未来更新可版本追踪（VERSION 绑定 git commit SHA + 文件依赖 + 变更影响检查）**。旧 `coze-guide` 仓库冻结不动作，本次全部改动落在本地工作区并最终推送 `coze-guize-V1`。

## 技术方案
| 维度 | 选择 | 理由 |
|---|---|---|
| 产物 | 纯 Markdown 文档规范仓库 | 无技术栈/无源码/无运行入口，`project_type=""`，不预览不部署 |
| 结构 | core / workflows / checklists / templates / references + INDEX / VERSION / 工作习惯 / 规范验证 | 按"规则权威源 / 流程执行 / 强制闸门 / 可复制模板 / 参考依据"五层切分，职责唯一 |
| 单一权威源 | `core/通用研发协议.md` 为全部条款原文源，其他文件只索引引用、不复制细则 | 消除双源漂移（延续仓库既有硬约束） |
| AI 导航 | `INDEX.md`（情况→文件→协议章节强映射），并在 `AGENTS.md` 指定"开工先读 INDEX" | 让 AI 按任务定位，不盲目加载全部文档 |
| 版本追踪 | `VERSION.md` 绑定 git commit SHA，登记各文件基线 + 文件依赖关系树 + 变更影响检查 | 人工 V13 只作展示别名，实际内容以 commit 为准 |
| 平台规则 | `references/平台专项规则.md`，标注"必须实测/官方文档取证，不凭空起草" | 堵住"平台规则凭印象写错"的洞 |

## 功能模块
- **core/通用研发协议.md**（唯一权威源）：保留现有协议 V13 全部条款；新增"适用范围分级"（通用/Coze/Web/Node/Git）+ 授权边界与确认点裁决 + 可部署态判据。作为所有其他文档的引用源。
- **core/任务执行与恢复.md**（执行参考）：汇总"无人值守执行循环 + 中断恢复 + 人类中途介入"为一份 AI 无人值守时的执行入口，内容索引自协议、不复制细则，避免漂移。
- **workflows/** 流程框架（必读·按阶段）：`需求与计划.md`、`开发测试与排障.md`、`Git与CI.md`、`交付上线与维护.md` —— 每份写"该阶段做什么 + 去读协议哪一节 + 用哪份 checklist"，是主线路标而非细则复制。
- **checklists/** 强制闸门（可逐条勾选验收）：`交付前检查.md`（每轮改动）、`上线前后检查.md`（含对抗测试与上线后核对）。
- **templates/** 可直接复制骨架：`AGENTS.md.template`、`项目接入.md`、`执行计划.md.template`、`交付报告.md.template`（新增）。
- **references/** 参考依据：`官方依据.md`（原 _依据核实.md）、`平台专项规则.md`（新增，标注实测取证）。
- **INDEX.md**：唯一导航总映射，把"任务类型 / 开发阶段 / 出现的问题"映射到"读哪个文件 + 协议哪一节 + 用哪份 checklist"。
- **VERSION.md**：git commit SHA 版版本登记 + 文件依赖关系 + 变更影响检查模板。
- **工作习惯.md**：用户长期偏好的常用规则（如"每次完成复查自检验证收口"），指明"接入时复制进项目 AGENTS.md"，与通用协议分离、可增量累积。
- **规范验证.md**：回答"规则是否真被 AI 读取/理解/执行/验证"的元治理方法 + 受控验证场景。
- **README.md**（门面）：这是什么、谁看、生命周期主线、新结构导航、接入三步。
- **AGENTS.md**（仓库自身记忆）：对齐新结构 + 长期偏好（截图不入库、历史改写需授权、本次结构重构说明）。

## 版本登记与基线
- 新仓库版本号：以 `git commit SHA` 为唯一可信版本标识；`VERSION.md` 中 `V13` 仅作人类易读别名并映射到当前 commit。
- 旧仓库 `coze-guide` 冻结；本次迁移在本地完成新结构后，由用户决定何时推 `coze-guize-V1`。
- `sub_id = "8a5f35c0"` 保持不变；`.coze` 更新 name 为 coze-guize-V1（如需）。

## 是否有原型设计
否（纯文档仓库，`project_type=""`，无 UI/页面，不适用设计引导）。
