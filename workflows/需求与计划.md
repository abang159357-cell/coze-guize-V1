# 工作流：需求与计划

> **层级**：workflows（流程框架）· **适用阶段**：生命周期 ①立项 → ②计划定案。
> **引用源**：细则以 `core/通用研发协议.md` 为准（尤其「协作模式」「§一 协作纪律」「§二 自动推进」）；本文件是阶段路标。

## 本阶段做什么

把人类模糊的目标收敛成**可执行、可验收、已授权的计划**。未定案不进入下一步。

| 动作 | 要点 | 依据 / 产出 |
|---|---|---|
| 1 理解需求 | 复述目标；方向性分叉先对齐（范围/技术路线/优先级），不凭印象动手 | README「生命周期主线」 |
| 2 定范围与排除项 | 明确本次做 / 不做（防目标漂移） | §一.3 |
| 3 定验收标准 | 每阶段有可勾选验收判据，不写模糊结论 | 协议「协作模式」计划模式 |
| 4 定授权边界 | 明确 AI 可自主范围 + 必停的危险操作清单 + 协作档位 | `docs/执行计划.md` 授权边界节 |
| 5 落盘计划文档 | 复制 `templates/执行计划.md.template` 到 `docs/执行计划.md` 并填实 | 未落盘不得进入无人值守 |
| 6 设计/原型先行 | 复杂项目编码前先落设计，与人类对齐后再实现 | §八.2 |

## 关键判断

- **这是不是"产品决策/不可逆/需授权"？** → 是则停在确认点，否则按 §二 连续推进。裁决见 `core/任务执行与恢复.md`「授权边界与确认点判定」。
- **需求是否已清晰？** 有分叉必问，方向定了就推进，不为提问而提问。

## 本阶段用哪份 checklist

计划阶段本身通常不触发交付检查；但一旦产出任何文件改动（如写入执行计划模板并填实），按 `checklists/交付前检查.md` 走。

## 常见问题索引

- 需求模糊、方向分叉 → 协议 §二、`core/任务执行与恢复.md`
- 不知道哪些操作需停下确认 → 协议「授权边界与确认点判定」、`core/任务执行与恢复.md`
- 计划文档写多细 / 何处唯一权威源 → `templates/执行计划.md.template`
