# 工作流：开发测试与排障

> **层级**：workflows（流程框架）· **适用阶段**：③无人值守开发（含开发/测试/排障）。
> **引用源**：细则以 `core/通用研发协议.md` 为准（§一纪律、§二自动推进、§三质量底线、§四自动测试、§九排障）；执行循环见 `core/任务执行与恢复.md`。

## 本阶段做什么

把已定案的计划拆成里程碑连续推进到「可部署上线状态」，每阶段带测试证据，异常能定位报告。

| 动作 | 要点 | 依据 / 产出 |
|---|---|---|
| 1 拆解并推进里程碑 | 按 `docs/执行计划.md` 逐里程碑推进，勾选进度 | `core/任务执行与恢复.md` 执行循环 |
| 2 最小必要改动 | 只做任务所需，不顺手重构、不为假想预留 | §一.4 |
| 3 质量底线 | 真接通非 Mock、正确性≠能编译、秘密不落地、安全编码 | §三 |
| 4 每功能带测试证据 | 静态防线 + 链路验证 + 回归测试，按风险优先 | §四 |
| 5 排障取证定位 | 先读日志报错定位到文件/行/堆栈再改，修一次验一次 | §九 |
| 6 阻断即停 | 同一问题凭证据试 1–2 次无新证据就停、如实报告 | §一.1、§九.5 |
| 7 里程碑汇报 | 按 §十一 汇报完成+证据+待办 | §十一 |

## 关键判断

- **改动可回滚 + 方向已确认？** → 连续推进；否则停。见 `core/任务执行与恢复.md`。
- **危险操作（删文件/重构大段/改核心逻辑）？** → 默认档暂停请人类确认。
- **验证方式**：web 用官方 `test_run`；其他类型按其类型 skill 验收协议。禁止用 shell 自验证绕过（§四）。

## 本阶段用哪份 checklist

- 每轮改动交付前：`checklists/交付前检查.md`。
