# 任务执行与恢复

> **层级**：core（规则权威源配套）· **性质**：AI 无人值守执行入口。
> **引用源**：本文件是 `core/通用研发协议.md` 中「无人值守开发执行流程 / 授权边界与确认点判定 / 中断恢复 / 人类中途介入」四条的执行化汇总。**细则一律以协议为准，本文件只索引引用、不复制条款原文**，避免双源漂移。协议变更时以协议为准，本文件仅同步执行入口链接。

## 触发前提

进入无人值守开发前，**计划必须已定案**（目标 / 范围 / 里程碑 / 每阶段验收标准 / 停止条件 / 授权边界均由人类确认），并已落盘 `docs/执行计划.md` 为唯一权威来源。**未落盘 `docs/执行计划.md` 的项目不得进入无人值守开发**（模板见 `templates/执行计划.md.template`）。

## 执行循环（AI 侧连续推进）

按协议「无人值守开发执行流程」8 环节推进：

| 环节 | 动作 | 协议依据 |
|---|---|---|
| 1 接收定案 | 读 `docs/执行计划.md`，拿到已确认目标与边界，不自行扩大范围 | §二 自动推进 |
| 2 拆解里程碑 | 拆成可验证里程碑（子目标 + 验收标准 + 危险操作点），同步维护进 `docs/执行计划.md` | Agent 模式"自主拆解任务步骤" |
| 3 进度跟踪 | 逐里程碑勾选记录进度，供中断恢复与人类查看 | §二.3 排队列连续执行 |
| 4 连续推进 | 按自动推进规则一口气推进，只在真实需人判断处停 | §二 |
| 5 阶段自检 | 每里程碑按自动测试机制给该阶段测试证据，未过不进下一阶段 | §四 |
| 6 危险操作闸门 | 删除文件 / 重构大段代码 / 修改核心逻辑等暂停请人类确认 | 危险操作需确认档、§十 |
| 7 里程碑汇报 | 按「回复与状态沟通」汇报已完成 + 证据 + 待办，更新 `docs/执行计划.md` | §十一 |
| 8 交付可部署状态 | 达到可部署态并附交付包后停下，交人类验收 | §五、§十.3 |

## 授权边界与确认点判定（唯一裁决）

> 一个动作是否为「确认点」，只看协议「授权边界与确认点判定」小节的**唯一裁决**，不分散拼凑。

- **推进速度维**——方向已确认 **且** 低风险 / 可回滚 → 连续推进；需产品决策 / 不可逆 / 需授权 / 破坏性 → 停在确认点。
- **风险闸门维**——「危险操作」一律先停；默认档 = `危险操作需确认`；仅当人类明确切到「运行所有指令」才自动执行。
- **工具执行权限 ≠ 业务授权**：能自动执行命令/改文件，不等于批准删除数据、改业务规则、覆盖生产环境等高风险业务操作。

**一句话裁决**：先问"是否产品决策 / 不可逆 / 需授权 / 破坏性 / 危险操作"——是 → 停；否 → 用 §二 判断"方向已确认 + 可回滚"——都满足 → 连续推进。

## 中断恢复（沙箱硬约束）

依据协议：沙箱空闲 1 小时自动中断连接。中断后**先核对状态再继续，不盲目重跑**：

1. 读 `AGENTS.md` / 计划，确认当前所处阶段与剩余里程碑。
2. 核对实际进度：任务清单勾选状态、git 历史、已改文件、已过/未过测试。
3. 核对运行环境：依赖 / 服务 / 预览是否仍可用（必要时重建）。
4. 从**最近已验证通过的里程碑**继续，不重复已过验收环节。
5. 证据不足或状态未知时先取证，不重跑可能产生副作用的操作。

## 人类中途介入（改方向 / 调整范围）

无人值守期间人类随时可插话调整需求或范围。AI 按以下顺序处理：

1. **先停**：暂停当前里程碑，不继续推进可能与新方向冲突的改动。
2. **记待办**：把进行中的工作状态、完成/未完成项记入 `docs/执行计划.md`（不丢弃已通过验证的成果）。
3. **重确认计划**：范围/目标/验收标准有变时，需人类**明确确认**变更后的计划；变更不明先问清再继续。
4. **更计划续跑**：更新 `docs/执行计划.md` 后，从受影响的最小里程碑重新推进，复用未受影响有效成果。

## 人类验收与上线归属

无人值守止于「可部署上线状态」；验收与部署由**人类（项目所有者）** 把持，AI 提供交付包与证据、**不替代上线闸门**。

> 可部署态的显式判据见 `core/通用研发协议.md`「无人值守开发执行流程」小节——阶段自检 + `checklists/交付前检查.md` + 自动化回归 + 探活冒烟 + `checklists/上线前后检查.md` 可上线。
